## Что это за проект
Telegram-бот на Python (`python-telegram-bot`, async) для спортивной аналитики матчей.

Основные пользовательские сценарии:
- просмотр матчей по спорту и дате;
- покупка/просмотр AI-анализа матча;
- пополнение баланса через DonationAlerts и автозачисление;
- доступ к купленным материалам в разделе «Мои анализы».

## Текущий статус архитектуры (важно)
- Основная точка входа: `main.py`.
- Платёжный флоу сейчас живёт в `user_handlers.py`.
- `payment_handlers.py` временно отключён (legacy-заглушка, хендлеры там не регистрируются).
- Синк матчей и очистка запускаются через APScheduler в `main.py`:
  - синк матчей: каждые 3 часа + при старте;
  - очистка старых данных: каждые 6 часов + при старте.

## Ключевые модули
- `main.py` — запуск приложения, регистрация хендлеров, планировщик.
- `user_handlers.py` — основная навигация, callback-routing, витрина матчей, покупка, пополнение, «Как это работает», поддержка.
- `keyboards.py` — inline-клавиатуры и callback_data.
- `database.py` — SQLite-схема, миграции, CRUD, topups/purchases/admins/generation_jobs.
- `sync_matches.py` — синхронизация матчей из TheSportsDB.
- `match_data_fetcher.py` — сбор данных по матчу для анализа.
- `ai_generator.py` — генерация анализа (DeepSeek/OpenAI-compatible API).
- `analysis_formatter.py`, `image_renderer.py` — форматирование/рендер анализа.
- `donationalerts_listener.py`, `da_polling.py`, `da_oauth.py` — интеграция DonationAlerts.
- `webhook_server.py` — вспомогательная серверная/вебхук-логика.
- `admin_commands.py` — админ-команды и управление.
- `utils.py` — общие утилиты (`safe_edit_message`, форматирование и т.д.).

## Инварианты меню и состояния
Проект использует stateful-навигацию через `context.user_data` и `menu_history`.

Требования:
- переход «вперёд» сохраняет текущий реально показанный экран в историю;
- «Назад» читает/делает `pop()` истории и не добавляет новые элементы в стек;
- экраны, зависящие от выбора пользователя, должны сохранять достаточный контекст (`sport`, `date`, `match_id`, источник перехода и т.д.).

## Правила внесения изменений
- Делай минимальный дифф, без рефакторинга «заодно».
- Без необходимости не меняй тексты кнопок и форматы `callback_data`.
- Для любых правок придерживайся порядка:
  1. Короткий план (файлы/точки/риски).
  2. Реализация.
  3. Проверка (тесты или ручной сценарий).

Если затронута БД:
- не делать разрушающие миграции без явного запроса;
- описывать изменения схемы и обратимость.

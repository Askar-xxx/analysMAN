# analysMAN - Руководство пользователя (Admin)

## Быстрый старт: от пустой БД до работающего бота

### Шаг 1. Установка зависимостей

```bash
pip install -r requirements.txt
```

### Шаг 2. Настройка конфигурации

Отредактируйте `config.py`:
- `TOKEN` - токен Telegram-бота (получить у @BotFather)
- `DEEPSEEK_API_KEY` - ключ DeepSeek API для генерации анализов

### Шаг 3. Инициализация базы данных

БД создаётся автоматически при первом запуске бота (`python main.py`) или вручную:

```bash
python -c "import database; database.init_db()"
```

Будут созданы таблицы: `matches`, `users`, `purchases`, `admins`, `teams`, `sync_meta`.

### Шаг 4. Наполнение БД матчами

#### Вариант А: Автоматически из TheSportsDB API (рекомендуется)

```bash
# Top-3 ближайших матча из топ-лиг (быстро, ~3 API запроса)
python sync_matches.py

# Все матчи на неделю из 5 лиг + 5 кубков (~28 API запросов)
python sync_matches.py --mode all

# Предпросмотр без сохранения в БД
python sync_matches.py --dry-run
python sync_matches.py --mode all --dry-run
```

**Доступные флаги:**

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--mode {top3,all}` | `top3` | top3 = 3 матча, all = все из 10 лиг/кубков |
| `--limit N` | `3` | Макс. количество матчей в режиме top3 |
| `--batch-size N` | `15` | Размер батча при сохранении |
| `--dry-run` | - | Только просмотр, без записи в БД |
| `--cache-teams` | - | После sync кэшировать данные команд |
| `--only-cache-teams` | - | Только кэширование команд (без sync) |
| `--db PATH` | `sports_bot.db` | Путь к файлу БД |
| `--verbose` | - | Подробный вывод |

#### Вариант Б: Добавить тестовый матч вручную

```bash
python add_test_match.py
```

Добавляет один тестовый матч (ЦСКА vs Динамо) на сегодня.

### Шаг 5. Кэширование команд (опционально)

После sync матчей можно загрузить подробные данные о командах.
Скрипт автоматически подождёт 65 секунд если sync был недавно (лимит бесплатного API).

```bash
# Отдельно (рекомендуется, чтобы не перегружать API)
python sync_matches.py --only-cache-teams

# Или вместе с sync (подождёт автоматически)
python sync_matches.py --mode all --cache-teams
```

### Шаг 6. Запуск бота

```bash
python main.py
```

Бот начнёт polling и будет отвечать на команды в Telegram.

## Admin-утилиты

### Проверка матчей в БД

```bash
python check_matches.py
```

Выводит все матчи из БД: ID, команды, дата, время, наличие анализа.

### Пополнение баланса пользователя

```bash
python add_balance_manually.py
```

Интерактивный скрипт. Запросит:
1. ID пользователя (Telegram user_id)
2. Сумму пополнения (в рублях)

### Очистка матчей

```bash
python clear_matches.py
```

Удаляет ВСЕ матчи из БД. Используйте с осторожностью.

### Добавление тестового матча

```bash
python add_test_match.py
```

Добавляет один матч на сегодня для тестирования.

## Типичные сценарии

### Ежедневное обновление матчей

```bash
# 1. Синхронизировать все матчи на неделю
python sync_matches.py --mode all

# 2. Проверить что добавилось
python check_matches.py

# 3. (Опционально) Подождать минуту, потом кэшировать команды
python sync_matches.py --only-cache-teams
```

### Полный сброс и пересоздание

```bash
# 1. Очистить матчи
python clear_matches.py

# 2. Пересоздать структуру БД (если нужно)
python -c "import database; database.init_db()"

# 3. Загрузить матчи заново
python sync_matches.py --mode all
```

### Повторный sync (idempotent)

Повторный запуск `sync_matches.py` безопасен - дубликаты не создаются.
Скрипт проверяет `api_event_id` и пропускает уже существующие матчи.

## Лимиты бесплатного API (TheSportsDB)

- Ключ: `"123"` (бесплатный, публичный)
- Лимит: ~25 запросов в минуту
- При превышении: HTTP 429 (скрипт автоматически ждёт и повторяет)
- Рекомендация: не запускать sync и cache-teams подряд без паузы в 1 минуту

## Структура базы данных

| Таблица | Описание |
|---|---|
| `matches` | Матчи (команды, дата, лига, стадион, анализ, цена, raw_json, source) |
| `users` | Пользователи (user_id, баланс, кол-во покупок) |
| `purchases` | Покупки (user_id, match_id, дата) |
| `admins` | Администраторы |
| `teams` | Кэш данных команд из API (TTL 24 часа) |
| `sync_meta` | Метаданные синхронизации (время последнего sync) |
